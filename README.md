# The TEA — この街に、余韻のある一杯を。

北海道のローカルティースタンド **The TEA** のホームページ制作用リポジトリです。TLH（Tea Laboratory Hokkaido）とは独立したサイトです。TLHのドメイン、沿革、活動実績やシステムは流用しません。

現在は、必要なカテゴリーを用意した**初期デザイン／サンプルサイト**です。ユーザー指定により、本文にはダミー・テスト文を使用しています。営業情報として誤解されないよう、画面上でもサンプルと表示しています。

## 方針

- 差別化の中心は「ローカル」。北海道のみなさんとの近さ、親しみやすさ、暖かさを表現。
- 2026-11-09の追加方針は、**親しみやすさと、シンプルで洗練されたラグジュアリーさの両立**。丸いスタンプ・太い文字・強い塗りを抑え、広い余白、細い罫線、軽めの見出し、直線的な写真配置で「こだわりのローカルティースタンド」を表現。
- 色の基準はユーザー指定の **CLASSIC MENU / QUICK MENU**。生成りと濃い茶色を軸とし、今回のデザインではグレージュの帯を細い境界線へ整理。金色や新しい配色は追加していません。
- フォントは **Noto Sans JP**。フォントファイルを同梱し、Google Fontsの外部通信は不要。
- HTML + CSSのみ。フレームワーク、ビルド処理、JavaScript、CMS、外部解析タグはありません。
- 折りたたみ式のお知らせ・FAQは、ブラウザー標準の `details` / `summary` を使用。
- 予約、購入、送信を装うボタンはありません。お問い合わせはユーザー提供のInstagramへ案内。
- 不足写真はユーザーの指示に従い「ここに○○の画像」という枠で保留。生成画像・架空の店舗写真・架空の製造工程は使いません。
- 同日の追加調整で、メイン・こだわり・店舗の写真領域を拡大し、囲み線と章の罫線を削減。メインと店舗は画面幅いっぱいに表示します。保留画像は撮影時の色調を示す代表色で塗り、案内文は維持しています。

## ファイル構成

```text
the-tea/
├─ dist/                         ← 配信するファイル一式。ビルド生成物ではなく、ここを直接編集
│  ├─ index.html                 ← ホームページの内容と構造
│  ├─ style.css                  ← 色・フォント・余白・スマホ対応
│  ├─ privacy.html               ← プライバシーポリシーの準備枠
│  └─ assets/                    ← Web用写真・実ロゴ・Noto Sans JP・フォントライセンス
├─ .openai/hosting.json          ← Sitesの識別情報と配信ディレクトリ。認証情報ではない
├─ .github/workflows/pages.yml   ← dist/だけをGitHub Pagesに自動公開する設定
├─ .gitignore                    ← Gitに入れないローカルファイル
└─ README.md                     ← この説明書
```

HTMLは見出しや文章の「意味と順番」、CSSは「見た目」を担当します。テキスト変更だけなら、まず `dist/index.html` を開きます。`dist` は配信範囲を明確にするための名前で、npmなどによるビルドは必要ありません。

## 起動・確認方法

### すぐに見る

`dist/index.html` をブラウザーで開いてください。インストール不要です。HTMLまたはCSSを保存したらブラウザーを再読み込みします。

### HTTPで見る

Pythonが使える場合は、このリポジトリで次を実行します。

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory dist
```

ブラウザーで `http://127.0.0.1:4173/` を開きます。終了はターミナルで `Ctrl+C`。PythonがPATHにない場合、この環境では次の同梱実行ファイルを使用できます。

```powershell
& 'C:\Users\inhok\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m http.server 4173 --bind 127.0.0.1 --directory dist
```

代表色は写真全体の主な色調の目安です。写真を単色に加工する指示ではありません。写真に置き換えたら塗りと案内文字は不要になります。オリーブだけは写真用に追加した色見本で、指定パレットの変更やICE/HOTの意味の変更ではありません。暗い写真保留面は生成りの文字、明るい面は茶色の文字にして、案内文のコントラストを確保しています。

写真の色見本を変える時は `style.css` の `--photo-*` を編集します。枠線を足すのではなく色面で配置を確認できる設計です。本文や他のセクションには影響しません。

例：トップの `<div class="image-placeholder hero-image"> ... </div>` 全体を、次のように置き換えます。以下は手順の例なので、画像ファイルを実際に用意するまで貼り付けないでください。

```html
<img class="hero-image"
     src="assets/hero-final.webp"
     alt="実際の写真の内容を説明する文章"
     width="2000" height="1100"
     fetchpriority="high">
```

外側の `figure.hero-visual` と `figcaption` は残します。これで写真下のキャプションと全体の配置を維持できます。こだわり・店舗も同じ考え方で、`craft-image` / `shop-image` をimgに付け、`loading="lazy"` を追加します。メニューの抹茶は枠を `div.menu-image` にし、その中に他の商品と同じimgを入れます。

トップのPC表示は画像の上にコピーが重なります。左側に明るい余白のある写真を選び、文字の読みやすさを確認してください。スマホではコピーと画像を別々に縦配置します。全幅は `.hero.wrap` / `.craft.wrap` / `.shops-section.wrap`、本文との余白は `--page-gutter`、大きな画面での揃えは `--wide-inset` が担当します。`100vw` を画像の幅に直指定するとスクロールバー分がはみ出す場合があるので、画像幅は親要素の100%を使っています。

画像追加時は、READMEの素材表を更新し、PC・スマホで被写体が切れないか確認します。写真の切り取り位置は `object-position` で調整でき、原本を破壊する必要はありません。

### GitHub Pagesの仕組みと更新方法

`.github/workflows/pages.yml` はGitHub公式のPages用Actionsで、`dist/` の内容を加工せず配信します。通常のサイト編集はHTML/CSSだけで完結し、ローカルのビルド環境は不要です。GitHub Actionsは公開のための処理で、訪問者のブラウザーでJavaScriptを実行するものではありません。

1. `dist/index.html`、`dist/style.css`、または素材を編集してローカル確認。
2. 変更をコミットし、`main` にpush。
3. GitHubの **Actions → Publish The TEA to GitHub Pages** が成功したことを確認。
4. 配信されたページを再読み込みして、内容を確認。

READMEだけの変更では再配信しません。手動で再配信したい時はActionsから **Run workflow** を選びます。Pages設定のSourceは **GitHub Actions** を使用します。`dist/` はブランチ方式のSourceでは直接選択できないため、このワークフローで配信対象を指定しています。
