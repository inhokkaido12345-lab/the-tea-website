# The TEA — 北海道の、いつもの一杯。

北海道のローカルティースタンド **The TEA** のホームページ制作用リポジトリです。TLH（Tea Laboratory Hokkaido）とは独立したサイトです。TLHのドメイン、沿革、活動実績やシステムは流用しません。

現在は、必要なカテゴリーを用意した**初期デザイン／サンプルサイト**です。ユーザー指定により、本文にはダミー・テスト文を使用しています。営業情報として誤解されないよう、画面上でもサンプルと表示しています。

## 方針

- 差別化の中心は「ローカル」。北海道のみなさんとの近さ、親しみやすさ、暖かさを表現。
- 色の役割はユーザー指定の **CLASSIC MENU / QUICK MENU** を参照。生成りを主な地色、濃い茶色を本文、グレージュを小さな見出し帯、ベージュを強調に使用。
- フォントは **Noto Sans JP**。フォントファイルを同梱し、Google Fontsの外部通信は不要。
- HTML + CSSのみ。フレームワーク、ビルド処理、JavaScript、CMS、外部解析タグはありません。
- 折りたたみ式のお知らせ・FAQは、ブラウザー標準の `details` / `summary` を使用。
- 予約、購入、送信を装うボタンはありません。お問い合わせはユーザー提供のInstagramへ案内。

## ファイル構成

```text
the-tea/
├─ dist/                         ← 配信するファイル一式。ビルド生成物ではなく、ここを直接編集
│  ├─ index.html                 ← ホームページの内容と構造
│  ├─ style.css                  ← 色・フォント・余白・スマホ対応
│  ├─ privacy.html               ← プライバシーポリシーの準備枠
│  └─ assets/                    ← Web用写真・実ロゴ・Noto Sans JP・フォントライセンス
├─ .openai/hosting.json          ← Sitesの識別情報と配信ディレクトリ。認証情報ではない
├─ .github/workflows/pages.yml   ← dist/だけをGitHub Pagesに自動公開する設定
├─ .gitignore                    ← Gitに入れないローカルファイル
└─ README.md                     ← この説明書
```

HTMLは見出しや文章の「意味と順番」、CSSは「見た目」を担当します。テキスト変更だけなら、まず `dist/index.html` を開きます。`dist` は配信範囲を明確にするための名前で、npmなどによるビルドは必要ありません。

## 起動・確認方法

### すぐに見る

`dist/index.html` をブラウザーで開いてください。インストール不要です。HTMLまたはCSSを保存したらブラウザーを再読み込みします。

### HTTPで見る

Pythonが使える場合は、このリポジトリで次を実行します。

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory dist
```

ブラウザーで `http://127.0.0.1:4173/` を開きます。終了はターミナルで `Ctrl+C`。PythonがPATHにない場合、この環境では次の同梱実行ファイルを使用できます。

```powershell
& 'C:\Users\inhok\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m http.server 4173 --bind 127.0.0.1 --directory dist
```

## 魔改造MAP — どこを直すと何が変わる？

| やりたいこと | 編集する場所 | 役割・影響範囲・初心者への注意 |
| --- | --- | --- |
| ブランドの色を変える | `style.css` 冒頭の `:root` | CSS変数は全体の共通設定。`--bg` は背景、`--ink` は本文、`--accent` は強調。小さな文字の読みやすさを確認 |
| 文字や太さを変える | `@font-face` と `--font`、各 `font-weight` | 全ページにNoto Sans JPを適用。フォントを交換するならライセンスも保存 |
| トップの言葉を変える | `index.html` の `#home` | `h1` はページの主題。長い言葉に変えるとスマホで折り返しが増える |
| トップ写真を変える | `.hero-photo` の `src` / `alt` | `src` はファイル位置、`alt` は写真の説明。切り取り位置はCSSの `object-position` |
| ロゴを変える | `assets/the-tea-logo.png` とHTMLの参照 | 実ロゴを書き出したコピー。PSDの原本を上書きしない。名前を変えたらfaviconも更新 |
| 紹介文を変える | `#about` の `.about-copy` | ブランド紹介。仮コピーの注記は内容の確認後に外す |
| 商品を増やす | `#menu` の `article.menu-item` | 記事全体を複製し、商品名・本文・画像・alt・価格を一緒に変更。3列から自動折り返し |
| 地域の活動を載せる | `#community` の `.coming-soon` | 準備枠を実内容に差し替える。未実施の活動を実績として書かない |
| 店舗を追加する | `#shops` の `article.shop-card` | `dl` の `dt` は項目名、`dd` は値。住所と地図は同時確認 |
| お知らせを書く | `.news-list` の `details` | `summary` が一覧タイトル、`p` が開いた本文。サンプル表示と日付を確認 |
| FAQを足す | `.faq-list` の `details` | 質問と回答をセットで複製。アレルギー・決済は確認済み情報で回答 |
| ナビを追加する | ヘッダーとフッターの `nav` | `href="#任意名"` と本文の `id="任意名"` を一致。idはページ内で重複させない |
| スマホの並びを変える | CSS末尾の `@media` | 条件内は狭い画面だけ上書き。PC用ルールを消さずに調整 |
| 検索・SNS表示を整える | HTMLの `head` | 正式URL決定後、canonicalとOGPを設定。ダミーがある間は `noindex` を維持 |

コード内にも、Webの一般的な概念、このサイトでの役割、変更するタイミング、影響範囲、初心者向けの注意をコメントしています。コメントは `<!-- HTML -->` と `/* CSS */` で、通常の画面には表示されません。

### GitHub Pagesの仕組みと更新方法

`.github/workflows/pages.yml` はGitHub公式のPages用Actionsで、`dist/` の内容を加工せず配信します。通常のサイト編集はHTML/CSSだけで完結し、ローカルのビルド環境は不要です。GitHub Actionsは公開のための処理で、訪問者のブラウザーでJavaScriptを実行するものではありません。

1. `dist/index.html`、`dist/style.css`、または素材を編集してローカル確認。
2. 変更をコミットし、`main` にpush。
3. GitHubの **Actions → Publish The TEA to GitHub Pages** が成功したことを確認。
4. 配信されたページを再読み込みして、内容を確認。

READMEだけの変更では再配信しません。手動で再配信したい時はActionsから **Run workflow** を選びます。Pages設定のSourceは **GitHub Actions** を使用します。`dist/` はブランチ方式のSourceでは直接選択できないため、このワークフローで配信対象を指定しています。

GitHub PagesのURLは [The TEA サンプルサイト](https://inhokkaido12345-lab.github.io/the-tea-website/) です。設定はGitHub Actions方式・HTTPS有効です。配信処理中は反映に時間がかかる場合があります。相対パスを使っているため、`/the-tea-website/` の下でも画像・CSS・フォント・ポリシーページを参照できます。ダミー表示と `noindex, nofollow` は維持します。

## 困った時

| 症状 | 確認すること |
| --- | --- |
| 変更が反映されない | 保存済みか、開いているファイルが `dist/index.html` か、ブラウザーを再読み込みしたか |
| 写真・フォントが出ない | `src` / `url()` の名前と大小文字、`assets` フォルダーの有無を確認。Windowsで動いても配信先では大小文字を区別する場合あり |
| ナビが飛ばない | リンク先の `#名前` と本文の `id` が一致し、重複していないか |
| スマホで横にはみ出す | 長い文章やURL、固定幅の指定を確認。隠してごまかさず幅や折り返しを直す |
| FAQが開かない | `details` の直下に `summary` があるか。閉じタグが途中で抜けていないか |
| 文字が違うフォントに見える | 初回ロード中は代替フォントが表示される。Noto Sans JPファイルの読み込み完了後を確認 |
| Instagramが開けない | アプリ・ネット接続・サービス側のログイン制限を確認。サイト内の架空ページに置き換えない |
